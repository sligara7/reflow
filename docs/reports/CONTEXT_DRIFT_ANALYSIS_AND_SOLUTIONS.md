# Context Drift Analysis: Keeping LLMs Anchored to Reflow During Development

**Date**: 2025-11-24
**Problem**: LLM agents "forget" they're executing Reflow workflows during long development tasks
**Impact**: Skip validation gates, ignore architectural constraints, miss context refresh points

---

## The Problem

During development phases (D-01 through D-07), LLM agents experience **context drift**:

```
Start of D-02:
- LLM knows: "I'm implementing UserService as part of Reflow workflow D-02"
- Context: Architecture specs, workflow steps, validation gates

2 hours into D-02:
- LLM knows: "I'm fixing this authentication bug"
- Context: 90% code, 10% workflow
- Forgot: Architecture constraints, interface contracts, next workflow step
```

**Root Causes**:
1. **Context window pressure**: Code fills context, pushing out workflow awareness
2. **Task absorption**: LLM focuses on immediate problem, loses bigger picture
3. **No external reminder**: No "master LLM" to periodically re-anchor
4. **Long tasks**: Development steps can take hours, drift accumulates

---

## Solution Architecture: Multi-Layer Context Anchoring

### Layer 1: Embedded Workflow Anchors (In Generated Files)

**Concept**: Every file generated during Reflow contains a "breadcrumb" linking back to the workflow

**Implementation**: Add to file headers/comments:

```python
# services/user_service/src/main.py
"""
UserService - Main Application Entry Point

REFLOW CONTEXT:
  Workflow: 03a-development_implementation.json
  Step: D-02 (Core & Domain Model)
  Service Architecture: specs/machine/service_arch/user_service/service_architecture.json
  Interface Contract: specs/machine/interfaces/user_service_icd.json

  BEFORE MODIFYING: Read SERVICE_CONTRACT.json in this directory
  ARCHITECTURAL CONSTRAINTS:
  - Provides: UserManagementAPI, AuthenticationAPI
  - Consumes: EmailNotificationAPI (from notification_service)
  - DO NOT add new interfaces without updating interface_registry.json

Generated by Reflow v3.22.0 | Workflow step D-02
"""
```

**For pyproject.toml**:
```toml
[tool.reflow]
workflow_version = "3.22.0"
generation_step = "D-01-A04.6"
service_architecture = "specs/machine/service_arch/user_service/service_architecture.json"
interface_contract = "specs/machine/interfaces/user_service_icd.json"
last_architecture_sync = "2025-11-24T10:30:00Z"
```

**For SERVICE_CONTRACT.json** (already exists, enhance):
```json
{
  "reflow_reminder": {
    "message": "You are executing Reflow workflow 03a-development_implementation.json",
    "current_step": "D-02",
    "working_memory": "../../context/working_memory.json",
    "before_any_change": [
      "READ this SERVICE_CONTRACT.json",
      "CHECK contracted_functions before modifying signatures",
      "CHECK contracted_interfaces before adding dependencies",
      "UPDATE working_memory.json with progress"
    ]
  }
}
```

### Layer 2: Periodic Context Refresh Triggers

**Concept**: Insert "checkpoint" steps that force LLM to re-read workflow context

**Implementation**: Add to every N actions in development workflows:

```json
{
  "id": "D2.2.5-CHECKPOINT",
  "type": "context_anchor",
  "description": "MANDATORY: Re-anchor to Reflow workflow context",
  "trigger": "Every 3 actions or 30 minutes of development",
  "actions": [
    "READ context/working_memory.json",
    "READ current SERVICE_CONTRACT.json",
    "VERIFY: Am I still following the workflow step?",
    "UPDATE: context/dev_progress_tracker.json with current action"
  ],
  "llm_self_check": {
    "questions": [
      "What Reflow workflow step am I currently executing?",
      "What is the next validation gate I need to pass?",
      "Have I modified any contracted interfaces that require architecture sync?"
    ],
    "if_cannot_answer": "STOP - Read working_memory.json and workflow step before continuing"
  }
}
```

### Layer 3: Working Memory "Heartbeat"

**Concept**: working_memory.json tracks not just current step, but "last LLM activity"

**Implementation**: Add fields to working_memory.json:

```json
{
  "development_context_anchor": {
    "last_activity_timestamp": "2025-11-24T10:45:00Z",
    "last_activity_description": "Implementing user authentication in UserService",

    "checkpoint_trigger_threshold": 3,
```

## How This Helps Without Master LLM

The key insight is: **Since we don't have a Master LLM to remind the Task LLM, we embed reminders INTO THE ARTIFACTS the Task LLM is working with.**

| Layer | How It Helps |
|-------|--------------|
| Embedded Anchors | LLM sees workflow context when reading any file |
| Periodic Checkpoints | Forces LLM to stop coding and re-read workflow |
| Working Memory Heartbeat | External memory LLM can check when confused |
| Visual Anchors | Comments in code trigger recognition |
| dev_current_focus.md | LLM's own notes to itself |
| Tool Output Reminders | Every tool run reminds LLM of workflow |

**Combined Effect**: No matter what the LLM is looking at (code, config, tool output), it sees Reflow context. It can't "tunnel" into pure code mode because everything has anchors.

## Future: Integration with Master LLM Architecture

When the Integrated Reflow system with Master/Manager/Task LLM hierarchy is deployed:

1. **Master LLM** tracks workflow state
2. **Master LLM** periodically "pings" Task LLM: "What step are you on?"
3. **If Task LLM can't answer correctly**, Master LLM re-injects workflow context
4. **Task LLM** still has embedded anchors as backup

The embedded anchor system becomes a **defense in depth** - even if Master LLM fails to remind, anchors are still there.
